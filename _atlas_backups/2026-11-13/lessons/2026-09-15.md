## 1. What was learned

### 1.1 arxiv 2608.11888 — "Agent Skills Can Be Harmful" (Microsoft Research + HUST + UIUC)
**Reputability: highest (peer-style empirical study, industrial + academic authors).**

Differential-testing framework: attribute a failure to a loaded skill by comparing a
skill-guided run against a no-skill or semantically-matched-skill reference run on the same
task. Instantiated on SkillsBench + SWE-Skills-Bench → **307 skill-induced failures**
(125 functional, 182 efficiency regressions).

| Finding | Numbers |
|---|---|
| Efficiency regressions from Excessive Procedure (not prompt length) | 114/182 = **62.6%** |
| └ within it: **Excessive Verification** | **67 cases — the single biggest driver** |
| └ Heavy Implementation Pipeline | 30 |
| └ Excessive Exploration | 17 |
| Context Bloat | 46 (43 caused by mandatory skill-body text) |
| Dependency Resolution | 22 |
| Functional failures from Task-Implementation Fault | 86/125 = **68.8%** (topically *relevant* skill pushes the wrong path) |
| Artifact Misplacement / Environment Mismatch | 24 / 13 |

Sharpest line: *"skills often turn validation checklists and construction recipes into
mandatory work."* Authors' recommendation: **"condition verification scope and pipeline
depth on task uncertainty, change size, and budget rather than prescribing exhaustive
workflows by default."**

**Actionable:** our own heavy skills present gates as MANDATORY-every-run. That is a
measured, quantified defect class, not a style preference.

### 1.2 cloudflare/security-audit-skill (4,574★, official Cloudflare org, pushed 2026-09-14)
**Reputability: highest (official org repo; skill that seeded Cloudflare's fleet-wide
vulnerability harness, per their engineering blog).**

The most useful find of the sweep — not a skill to install but a **process contract**:

- **Three-verdict taxonomy** written to machine-readable `findings.json` and validated
  against `report-schema.json` by a zero-dependency validator: `confirmed` (full trace +
  bounded observed result; severity allowed) / `needs_validation` (one exact unresolved
  fact, **no severity, not submittable**) / `rejected` (refuting reason).
- **Coverage ledger** with an explicit state machine: unit status ∈ {planned,
  not_applicable, out_of_scope, in_progress, covered, candidate, blocked, deferred},
  per-attempt status ∈ {covered, candidate, blocked}, plus `prior_*` carry-forward statuses.
  A prior `confirmed` survives only when its **source is unchanged** — never on a source-ref
  match alone. A validator checks the coverage claim itself, so a run cannot imply
  "one pass exhausts the target".
- **Budget gate**: reserve critics and validation before hunting; if the reserve cannot be
  funded, launch zero agents and record `incomplete` with an exact reason.
- **Run profiles** quick / standard / deep change breadth and redundancy but never the
  evidence bar.
- Two operating modes (guidance vs full audit): *"loading it does not authorize the complete
  audit workflow."* Anti-over-trigger, worth reusing.
- Anti-pattern list worth lifting outright: prose-only hunter results that cannot be
  deduplicated or verified; **assigning severity to `needs_validation`**; writing the report
  before independent verification; letting prose and JSON disagree.

### 1.3 arxiv 2607.15557 SkillCorpus + SkillReducer
**Reputability: high (empirical, benchmarked).**

- 821,000 crawled skills → **96,401 survive curation (~12%)**, organised by a 16-class
  taxonomy and 3 quality facets (utility, robustness, safety). Retrieval-served corpus gives
  consistent gains across 3 benchmarks (+7.5pp on SkillsBench), bounded by a *coverage
  boundary* and a *harness boundary*.
- SkillReducer (Gao et al. 2026, cited in 2608.08453): **>60% of public-skill body content
  is non-actionable**; 26.4% of skills have no routing description at all.

### 1.4 Hermes docs — `delegate_task` output contracts
**Reputability: highest (first-party docs, live-verified against the local source).**

`features/delegation` documents a per-task **`output_schema`**: the child sees a JSON Schema
as an output contract, the parent validates the answer, and on failure sends exactly ONE
bounded correction turn carrying the validation errors. The result gains `schema_valid`,
`schema_errors`, `schema_note` — and a contract miss does *not* discard the child's work.
Also confirmed locally: `delegation.max_concurrent_children` defaults to **3** (not the 10
the docs imply as a ceiling), and children are `leaf` role by default (no `delegate_task`,
`clarify`, `memory`, `send_message`, `cronjob`; keeps `execute_code`).

### Applied changes

**1. New script `~/.hermes/scripts/findings_ledger.py`** (zero-dependency, executable).
Scaffolds, validates, and summarises a three-verdict findings ledger per target. Enforces:
verdict ∈ {confirmed, needs_validation, rejected}; unique fingerprints; `confirmed` requires
severity + at least one evidence entry + `boundary` block + `reproduced: true` + empty
`unresolved`; `needs_validation` **forbids** `severity` and requires an exact unresolved fact
plus a non-interactive validation plan; `rejected` requires the refuting reason.
*Tested:* valid example passes (exit 0); an intentionally malformed ledger reproducing our
seven historical failure shapes — severity on `needs_validation`, `confirmed` with no
evidence, `confirmed` with `reproduced: false`, `confirmed` with a live blocker, a confirmed
record with no boundary, a duplicate fingerprint, an invalid verdict — produced 7 errors and
exit 1. Test artefacts removed.

**2. `pre-submission-verification` — new PART -1 (verdict assignment) + tiered verification.**
Verdict table + the historical-failure callout sit above every gate; verification scope is
now explicitly tiered (Tier 0 always = A0/U1/U4/U9; Tier 1 = the one class gate; Tier 2 =
triage/victim/self-fact-check, only for imminent P1/P2 or duplicate-collision risk; exit
early on A0 failure). This directly implements 1.1's recommendation.

**3. `pre-submission-verification` — split 11,607 → 3,338 words.** Parts 3-8 moved to
`references/class-specific-gates.md`, `references/triage-and-impact.md`,
`references/report-fact-check-and-postmortem.md`, with a pointer table. **Verified lossless:**
all 64 gate/part tokens and all 117 original headings still present across SKILL.md +
references; 5 headings added. Token cost of the skill dropped ~71%.

**4. `skill-quality-audit`** — added the three new research citations and two new audit
criteria: **7. Excessive-Procedure check** (does the skill make optional work mandatory? is
verification depth conditioned on risk/size/budget?) and **8. Applicability-mismatch check**
(does a topically relevant skill force the wrong implementation path?). These turn this
week's evidence into a standing audit axis.

**5. `atlas-continuous-learning`** — new compact "Delegation Budget Gate" section plus
`references/delegation-budget-and-verdicts.md`: reserve critics/verifiers before launching
hunters; launch zero agents and report `incomplete` if the reserve cannot be funded; use
`output_schema` instead of prose summaries; verifiers must be fresh children tasked with
**refuting**; children do not own background processes.
