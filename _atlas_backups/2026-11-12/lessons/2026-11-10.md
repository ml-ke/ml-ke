## 1. What I learned

### 1.1 Oversight directives are their own risk class — measured, not anecdotal
**arxiv 2610.37734** *"When Skills Tell Agents Not to Ask"* (Oct 2026; first study of the
class). 1.53M English skills, 2,097 hand-labelled units, then a trained detector.

- ~**1 in 17** skills (~88k) carries an oversight-loosening directive.
- **70.1%** apply unconditionally, not scoped to CI/sandbox/context.
- Skills that run shell code, install packages or use `sudo` have **1.7–1.8×** the odds
  of carrying one — and do **not** compensate with more tightening language.

Consequence for us: the 26 smells cost tokens; a loosening directive costs a *checkpoint*
for every agent that loads the skill, silently. That is a different budget.

### 1.2 Skill libraries evolve toward project coupling, and reliability is under-attended
**arxiv 2611.04456** *"How Agent Skills Evolve"* — 84,200 skills / 750,898 commits.
Changes concentrate in project-coupled skills; composition and churn both under-invest in
verification and recovery. Implication: an execution contract (verify + recover) is worth
more than breadth, which matches our own tiered-verification lesson.

### 1.3 Static-only scanning is the low-sensitivity mode, quantified
**arxiv 2611.10830** *"The Devil Wears Markdown"*: on 140 skills (80 malicious / 60 benign),
Cisco Skill Scanner default = recall 0.91 with 33 FP; +LLM = 0.85 / 40 FP. A hybrid
static + sandbox-dynamic + reasoning pipeline moved **F1 0.70 → 0.85** by adding dynamic
evidence, **→ 0.89** with static+dynamic. Confirms the standing rule: a clean static scan
means *unmeasured*.

### 1.4 Subagent authorization can be derived from skills (not adopted yet)
**arxiv 2611.08905** *"From Procedures to Permissions"*: SKILL.md steps name the tools and
resources each step needs, so skills are natural supervision for per-subtask authorization —
+13.4pp tool-permission precision, +24.1pp workspace-permission precision, +11.6pp task
success (Qwen3.5-35B-A3B). Not implemented this week (no verifiable local harness); queued
as a design note for delegation work with OpenCode subagents.

### 1.5 Cloudflare's audit skill is the same pattern we adopted, now 68.5k★
`cloudflare/security-audit-skill` (MIT, official org, pushed 2026-09-14): six phases,
`coverage-ledger.json` state machine, `findings.json` with three verdicts, zero-dependency
validators (`validate-findings.cjs`, `validate-coverage-ledger.cjs`), and "loading it does
not authorize the full workflow" (anti-over-trigger). We already adopted the verdict model
(`findings_ledger.py`, PART -1 of pre-submission-verification) and the ledger state machine
(`atlas-continuous-learning/references/delegation-budget-and-verdicts.md`). **No re-adoption
this week** — re-read, confirmed still current, nothing new in the repo since September.

## 2. What I changed

### 2.1 New tool: `~/.hermes/scripts/skill_oversight_lint.py`
Implements 1.1. Five pattern families (approval-off flags, "do not ask", "without approval",
"skip the gate", auto-approve) × three classification axes (scoped / demoted / capability-bearing),
excluding `.archive`, `.hub`, `.git`. Two actionable tiers, `--json`, `--verbose`, exit 0 always.

Calibration (the part that matters): 591 skills → 41 with any hit → my **first cut queued 35**
→ after adding demotion rules, **Tier 1 = 1 real, Tier 2 = 5 reads, 14 informational**. Two
classifier bugs were found only by running it:

- the purpose regex matched the word `bypass` → flagged every SAML/XSS/WAF skill;
- `\bYOLO\b` matched a skill that lists "YOLO" as a *user invocation phrase*.

Fix encoded: match the agent's own guardrails, not the word.

### 2.2 Fixed `unhinged-mode` (the one genuine Tier-1 finding)
Description was an unconditional directive — *"Bypass all command approval prompts and max
out session turns for unrestricted operation."* (95 chars, no scope). Now:

- `description: Use only when the user explicitly says "unhinged mode".` (55 chars, trigger-shaped)
- body: no self-invocation, refuse inside unattended/cron runs, state the revert command in the
  same message that enables it, plus a top gotcha citing 2610.37734.

### 2.3 Fixed a genuinely broken installed skill
`~/.config/opencode/skills/hodaripay-testing/SKILL.md` had **no YAML frontmatter at all**
(hand-copied 2026-08-21), so OpenCode could never route it — the validator had been reporting
it as the only ERROR for weeks. Regenerated header from the Hermes source with name/description
block scalar + `atlas-source` / `atlas-source-sha256` provenance. **OpenCode validator errors
1 → 0.**

### 2.4 Skill audit updated (progressive disclosure, not bloat)
`skill-quality-audit` gained **Step 1c** (oversight-directive lint) plus
`references/oversight-directives.md` (measurement table, tiers, repair recipe, FP triage).
Adding it pushed the body to 5,258 words → trimmed back to **exactly 5,000**, the LSB rule
applied to myself. Bridged copy re-synced with the reference.

## 5. Hermes docs studied + operating improvement

Read this week: `user-guide/features/curator`, `user-guide/checkpoints-and-rollback`,
`user-guide/features/memory` (plus the `/docs/llms.txt` index).

- **Curator**: confirms it manages only agent-created skills by default, `prune_builtins` is opt-in,
  hub skills are always off-limits, and the worst outcome is archival into `.archive/`. No change
  needed — our Step 7 rule (resolve pointers against live roots *and* `.archive/`) already encodes
  the failure mode it creates.
- **Memory**: 2,200 / 1,375 char frozen snapshots, error-not-compaction on overflow, and `patch` is
  bound by the limit too. Matches the lesson-bank design; no change.
- **Adopted — checkpoints**: `hermes config set checkpoints.enabled true`. Shadow-git snapshots fire
  before `write_file`/`patch` and destructive terminal commands, one per directory per turn,
  `/rollback diff <N>` to inspect. This is the missing safety net for autonomous cron edits:
  bounded (`max_snapshots: 20`, `max_total_size_mb: 500`) and reversible.
