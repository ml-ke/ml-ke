## 1. What was learned

### 1.1 Audit the collection, not just each skill — SkillSeam's six seams
**Source:** arxiv 2609.13321 *SkillSeam: Six Principles for Auditing Agent Skill Collections* (Sep 2026, empirical).
A library of individually competent skills is not a reliable system: skills fail at the **seams**.
Six properties were perturbed in one sealed skill system, each mapped to its own failure channel:

| Principle | Measured effect of breaking it |
|---|---|
| Persistence gradient | flattened summary→detail hierarchy: **+60% loaded-skill tokens** |
| System coherence | dangling anchor (pointer to a missing file/skill): **+64% tokens, −3.1pp accuracy** |
| Regime gating | synonymous alias/duplicate dir: noncanonical routes **0/32 → 15/32**, half of matched paraphrases flipped |
| Orthogonal coverage | overlapping lanes: ownership conflicts **0/16 → 14/16** |
| Flow | bland triggers: routing conflicts **3/32 → 30/32**, **3.7×** loaded tokens |
| Granularity discipline | granularity mis-mix: **−12.5pp accuracy — the largest single drop** |

**Adoptable, and adopted:** a collection-level audit axis. Our 26-smell taxonomy stops at the file
boundary; this is the missing layer.

### 1.2 A single scanner's verdict is not evidence
**Sources:** arxiv 2609.17274 *After the Party* (OpenClaw registry governance, 61,990 skills) and
arxiv 2609.14079 *SkillSecurer*.
- Three security scanners **disagreed on 23,702** of the 61,990 skills all three covered.
- After human adjudication, weighted sensitivity was **21.67% – 61.06%**.
- 85.06% of readable skills carry privilege evidence; 77.86% have zero stars/comments.
- SkillSecurer's LLM-in-the-loop design was the only compared scanner to reach **100%** injection
  detection; it found latent injection risk in **>17%** of sampled popular public skills.

**Adoptable:** stop treating our single static scan as a clean bill of health; add an independent
second pass. **Adopted** — bounded to changed skills only.

### 1.3 Invocation changes whether a skill helps: subagent over main context
**Source:** arxiv 2609.09233 *Subagents vs Agent Skills*.
Loader-style execution (skill instructions into the main context) becomes brittle as task horizons
grow, because reasoning degrades as context accumulates. Invoking the same skill package as a
**subagent with a fresh context** wins — *when the skill exposes a clear input/output contract*. The
cost is coordination tokens. This independently validates the `delegate_task` + per-task
`output_schema` pattern we adopted on 2026-09-15 and gives it a selection rule.
**Adoptable, adopted as guidance.**

### 1.4 `gh skill` — an official GitHub discovery surface (gh ≥ 2.98.0, preview)
**Source:** gh 2.98.0 CLI (`gh skill --help`) + github.blog changelog. Commands: `search`,
`preview`, `install`, `list`, `update`, `publish`. It returns repo, path, description and a
popularity count, and surfaces non-English descriptions that English keyword searches miss.
**Gotcha (verified on this machine):** installs default to `~/.agents/skills/`, which OpenCode
only loads if that root is reachable — a default-scope install can be silently inert.

### 1.5 Registry survival is not explained by size or downloads
**Source:** arxiv 2609.17274. Top 10% of skills took **46.93%** of all downloads; no simple feature
(size, downloads) predicted continued listing once creation cohort and skill age were controlled;
monthly listing creation and core-repo activity were already falling from their spring 2026 peaks.
Practical read: popularity signals in a skill registry are weak evidence — evaluate content.

## 4. Hermes docs studied + operating improvement adopted

**Pages read this run:** `user-guide/checkpoints-and-rollback` and `user-guide/egress/iron-proxy`
(both new to the sweep), plus the docs index via `llms.txt`.

- **Checkpoints & rollback** — off by default (opt-in as of v2, shadow-store cost). When on, it
  snapshots before `write_file`/`patch` and before destructive terminal commands (`rm`, `mv`, `sed -i`,
  redirects, `git reset/clean/checkout`), one checkpoint per directory per turn, with
  `hermes checkpoints status|prune` for the store. **Improvement adopted:** recorded in the sweep
  reference as the correct safety net for a subagent that writes to disk during a hunt — cheaper
  than deleting a skill copy by hand, and it makes "I removed it" recoverable. The shadowed-copy
  removal above was done with an explicit `cp -a` backup because checkpoints are off on this host;
  worth enabling globally if unattended file-removal work increases.
- **iron-proxy egress credential injection** — Docker-backend only (Modal/Daytona/SSH/Singularity
  don't get proxy env vars yet); the sandbox holds opaque proxy tokens, the host daemon swaps in the
  real key after TLS termination. Not applicable to this local-backend host, but it *is* the correct
  answer to "a prompt-injected agent in a sandbox reads `~/.hermes/.env`", which is exactly the
  threat model our skills now warn about. Recorded as the answer whenever sandboxing is added.
