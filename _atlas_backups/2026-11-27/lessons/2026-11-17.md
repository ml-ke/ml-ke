## 1. What was learned

### a) A skill's value is carried by the *rule*, and rules that name a path/command are the ones that land
arxiv **2610.04832** "Agent Skill Evolution: How Revisions Affect Coding Agents" (Oct 2026; arxiv = high reputability).

- 2,608 first/last revision pairs of 3,159 skills: **55% of revisions change a rule or procedure**.
- An added rule raises single-answer compliance **+0.41** on 16 open-weight models; across four sandboxed agents the rate of taking the required action rises **+0.23** (range +0.16..+0.36) and judged final correctness **+0.10**.
- **"The gain comes mainly from rules that name a command or path the old Skill did not mention."** Concrete > abstract, measured.
- Real tools load the body lazily, and that halves the effect: agents keep **~51%** of the action gain (open models ~38%).
- Cost: a revision adds 18-19% input tokens to a single answer; loading a body raises episode tokens **+50%**.

Consequences for ATLAS: (i) prefer edits that add/repair a *named* command or path over prose rewrites; (ii) a skill whose named path does not resolve is worse than no rule at all — the instruction becomes a search; (iii) since lazy loading halves the gain, always-resident rules (SOUL.md) remain the right home for invariants.

### b) The same skill helps one harness configuration and hurts another
arxiv **2610.08875** "An Empirical Study of Agent Skills' Downstream Utility" (v2, Oct 2026; arxiv).
- 87 SkillsBench tasks × 9 configurations: the same skills help some configurations and hurt others on **36.78%** of tasks; traces show "recommended procedures can become an execution burden" — the Excessive-Procedure result, now measured per configuration.
- Relevance ranking **overlooks more useful candidates**; reranking by *support for the required operations* raises first-choice pass rate **+4.35..5.80pp**.
- **Stage Plan and Dependency DAG beat use-order alone**; DAG's extra benefit is concentrated in tasks supplied 5-6 skills. 17 authoring practices, incl. linking procedures to recovery and **checks on final artifacts**.

Consequences: at our scale (~280 skills, 1-2 loaded per task) a DAG builder is not justified — but the "check the final artifact, not the procedure" rule already matches `pre-submission-verification` and Step 8. Recorded as a watch item, not built (anti-churn).
